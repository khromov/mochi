# Mochi 0.8.0

Mochi 0.8.0 is out — 93 commits and 63 pull requests since [0.7.0](https://github.com/khromov/mochi/blob/main/packages/mochi/CHANGELOG.md) — the biggest release so far. The main features in this release are:

## Queues

[`Mochi.queue()`](/docs/queues/) moves work off the request path — sending email, encoding media, calling a slow API. Like `Mochi.page` / `api` / `ws`, it returns an inert config you mount in `Mochi.serve()`, so every background queue is declared in one place. It runs in your process, backed by [bunqueue](https://bunqueue.dev/)'s embedded mode.

```ts
await Mochi.serve({
  routes,
  queues: {
    emails: Mochi.queue<{ to: string }>({
      concurrency: 10,
      process: async (job) => sendEmail(job.data.to),
    }),
  },
});

await Mochi.getQueue<{ to: string }>('emails').add('send', { to: 'alice@example.com' });
```

## Email

[`Mochi.email()`](/docs/email/) sends transactional mail. Configure a transport once under `Mochi.serve({ email })`, then send from a page action, an API route or a queue job. Templates can be Svelte components rendered to inlined HTML.

```ts
await Mochi.email({
  to: 'alice@example.com',
  subject: 'Reset your password',
  html: '<p>Click <a href="…">here</a> to reset.</p>',
});
```

## Images

[Images](/docs/images/) are transformed on the fly with `Bun.Image` and served from a stale-while-revalidate disk cache. Declare transforms once as named sizes; `<Image>` only mints a signed URL, so SSR never blocks on image work. URL payloads are encrypted, so nobody can request arbitrary sources or transforms through your server. Local files can be imported Vite-style and carry their intrinsic dimensions.

```ts
await Mochi.serve({
  image: {
    sizes: {
      thumbnail: { width: 200, height: 200, fit: 'inside', format: 'webp', quality: 80 },
    },
  },
  routes,
});
```

## Captcha

[`<MochiCaptcha />`](/docs/captcha/) is a slide-to-verify widget with proof-of-work and replay protection — no third-party service, no tracker. Mint a challenge in `serverProps` with `mintCaptcha()`, render the component, call `verifyCaptcha()` in the action.

## Rate limiting

Any `Mochi.page()` or `Mochi.api()` route takes a [`rateLimit`](/docs/rate-limiting/) config, with memory, SQLite and Postgres stores available. API routes get a `429` JSON body; page routes render your error page with status `429`.

```ts
'/api/data': Mochi.api(handler, {
  rateLimit: { limit: 100, window: '1m' },
}),
```

## `mochi:clientOnly`

Some components can't render on the server at all — canvas, `localStorage`, third-party browser SDKs. [`mochi:clientOnly`](/docs/client-only/) emits an empty island wrapper during SSR and mounts the component in the browser, with optional fallback markup as children. There's a `:visible` variant that waits for the viewport.

```svelte
<AudioVisualizer mochi:clientOnly />
```

## Logging and the CLI

Which severity each framework event lands on is now remappable per app via the `consoleLogger:level` [filter](/docs/extensions/) — promote what you care about, demote what you don't, without moving the [global level](/docs/logging/). The CLI also got its own [reference page](/docs/cli/), covering `build`, `generate-key` and `update-skill`.

## Install or upgrade

New project:

```sh
bun create mochi@latest my-app
```

Existing project — bump the dependency and restart the dev server:

```sh
bun add mochi-framework@latest   # or @0.8.0 to pin
bun run dev
```

Two things worth doing after upgrading. Image and captcha URLs are signed with `MOCHI_KEY`, so mint one if you don't have it yet:

```sh
bunx mochi-framework generate-key
```

And if you code with an AI assistant, refresh the [agent skill](/docs/docs-for-llms/) so it knows about the new APIs:

```sh
bunx mochi-framework update-skill
```

The [full changelog](https://github.com/khromov/mochi/blob/main/packages/mochi/CHANGELOG.md) has everything else, including the performance work on builds and dev HMR. Mochi is still early and in alpha — if something breaks, [Discord](/discord/) or a [GitHub issue](https://github.com/khromov/mochi/issues) both work.
