# Mochi on Bun 1.4.0

Bun 1.4.0 is the first version of Bun written in Rust. Version 1.3.14 was the last one written in Zig; over eleven days in May 2026, the Bun team ported all 1,448 `.zig` files to Rust — 6,502 commits produced by roughly 64 Claude agents running in parallel, with every file passing through one implementing agent and two adversarial reviewers. The full story is in the [Bun blog post](https://bun.com/blog/bun-in-rust).

Mochi sits directly on top of the runtime that just got rewritten. This post walks through what actually changed under each Mochi subsystem — and what you have to do about it (spoiler: nothing).

## Why they rewrote it

Bun's hardest bugs came from one structural problem: garbage-collected JavaScriptCore values interleaved with manually managed Zig memory. Zig's `defer`-based cleanup meant every allocation's lifetime had to be tracked by hand at every call site, and the misses showed up as use-after-frees, double-frees, and leaks in `node:zlib`, `node:http2`, `Buffer`, and friends.

Rust moves that entire class of bug to compile time: the borrow checker enforces lifetimes, and `Drop` makes cleanup automatic. On top of that, the rewrite brought Miri and 24/7 coverage-guided fuzzing into CI. About 4% of the Rust code is `unsafe` (mostly one-line FFI calls into JavaScriptCore), shrinking as the code is made idiomatic.

Crucially, nothing user-visible changed: JavaScriptCore is still the engine, and the same 60,624+ test cases pass with zero tests skipped or deleted.

## The numbers

- HTTP throughput: **+2.8–4.8%** across `Bun.serve`-based servers.
- Binaries: **18–20% smaller**.
- Memory: 2,000 consecutive `Bun.build()` calls went from **6,745 MB leaked to 609 MB used** — an 11× reduction.

## What this means for each Mochi subsystem

**`Bun.serve()` — every request you handle.** `Mochi.serve()` is a thin layer over `Bun.serve`: every page render, `Mochi.api()` call, WebSocket frame, and SSE stream flows through it. The throughput gain applies across the board, and long-lived connections (`Mochi.ws()`, `Mochi.sse()`) sit exactly where lifetime bugs used to live — a socket closing mid-write is the classic use-after-free shape that the borrow checker now rules out.

**`Bun.build()` — the component registry.** Mochi's `ComponentRegistry` compiles every Svelte page for SSR and builds client bundles for each hydratable island by calling `Bun.build` — repeatedly, on every file change in dev. That makes the build-leak fix the single most tangible win for Mochi development: a long dev session used to slowly accumulate bundler memory; on 1.4.0 it stays flat.

**`bun:sqlite` — cache and queues.** Mochi's cache and queue primitives persist through `bun:sqlite`. Same API, same bytes on disk, now with the native binding layer under Rust's memory guarantees.

**`Bun.file` — static assets.** Everything served from `public/` goes through `Bun.file`. Nothing to change; it's simply part of the hardened surface now.

## What you have to do

Nothing. The rewrite shipped with zero breaking changes, so upgrading is:

```sh
bun upgrade
bun --version # 1.4.0
```

Mochi's test suite passes on 1.4.0 unmodified. You get the throughput, the smaller binary, and the flat dev-server memory profile for free — which is exactly how a runtime upgrade should feel.
